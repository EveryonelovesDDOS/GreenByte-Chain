# 🌱 GreenByte

## AI Carbon Measurement, Comparison & Verification

> **Every Prompt Has a Carbon Cost.**  
> **Measure it. Compare it. Verify what local AI saves.**

GreenByte is a proof-of-concept platform for **prompt-level AI carbon measurement, cloud-vs-local comparison, and verifiable sustainability records**.

Instead of asking users to manually estimate tokens, electricity or carbon emissions, GreenByte connects to AI runtimes in the background, captures inference telemetry, compares Cloud AI against Local AI, calculates estimated carbon impact, and generates a tamper-evident impact record.

The long-term vision is to deploy Local AI on a **repurposed smartphone powered by solar-assisted energy**, allowing GreenByte to measure how much environmental impact can potentially be avoided by shifting suitable AI inference from cloud infrastructure to local edge devices.

---

## 🎯 Project Goal

Most AI applications show users the answer generated by the model, but provide little visibility into the environmental impact behind that inference.

GreenByte explores three questions:

1. **How much AI workload was used?**
2. **How different is the environmental footprint of Cloud AI and Local AI?**
3. **Can the resulting sustainability record be independently verified?**

GreenByte addresses these questions through three layers:

| Layer | Purpose |
|---|---|
| **Measure** | Capture AI tokens, runtime and energy telemetry |
| **Compare** | Convert Cloud and Local energy into estimated CO₂e |
| **Verify** | Hash the evidence and create a tamper-evident sustainability record |

# ⚡ Local Energy Measurement

GreenByte currently measures incremental Local AI GPU energy using NVIDIA power telemetry.

The principle is:

```text
Energy (J)
=
Power (W)
×
Time (s)
```

More generally:

```text
Gross GPU Energy
≈
∫ P(t) dt
```

GreenByte also measures an idle GPU baseline:

```text
Baseline Energy
=
Idle GPU Power
×
Inference Runtime
```

Then:

```text
Net Local Inference Energy
=
max(
    0,
    Gross GPU Energy
    -
    Baseline Energy
)
```

A completed preliminary benchmark recorded values such as:

```text
Idle GPU Power       : 15.663 W
Average GPU Power    : 22.560 W
Gross GPU Energy     : 2.407 J
Baseline Energy      : 1.671 J
Net Inference Energy : 0.736 J
```

A separate five-run test produced:

```text
Average Net GPU Energy : 1.156 J
Median Net GPU Energy  : 0.736 J
```

This is **GPU telemetry-derived incremental energy**, not total laptop wall-plug electricity.

# ☁️ Cloud Energy

Ollama Cloud provides actual runtime telemetry such as token counts and inference duration, but does not currently expose the actual data-centre energy consumed by a request.

Therefore the current GreenByte PoC uses a transparent **testing-only cloud energy estimator**.

Current prototype formula:

```text
Ecloud
=
α
+
βin × Input Tokens
+
βout × Output Tokens
```

Current testing coefficients:

```text
α    = 250 J
βin  = 2 J/input token
βout = 7 J/output token
```

For the current Cloud test:

```text
Input Tokens  = 8
Output Tokens = 50
```

Therefore:

```text
Ecloud
=
250
+
(2 × 8)
+
(7 × 50)

=
616 J
```

> **Important:** 616 J is a GreenByte prototype testing estimate. It is not energy data measured or disclosed by Ollama Cloud.

The cloud coefficients will eventually be replaced by measured, provider-disclosed or research-calibrated values.

GreenByte converts energy into estimated carbon emissions.

```text

=
```

### Local

```text
Local CO₂e
```

# 🧬 Hash Structure

### Methodology Hash

Represents the methodology and calculation parameters associated with the record.

### Evidence Hash

Represents the inference evidence, including tokens, energy, carbon result and ACU.

### Block Hash

Connects the verified evidence to the GreenByte Ledger.

Conceptually:

```text
Methodology
     ↓
SHA-256
     ↓
Methodology Hash
     │
     ▼
Inference Evidence
     ↓
SHA-256
     ↓
Evidence Hash
     │
     ▼
Ledger Block
+
Previous Block Hash
     ↓
SHA-256
     ↓
Block Hash
```

If stored evidence is modified later, the recalculated hash will no longer match the original record.

# 📜 Certificate, Proof & Verify

Every verified impact record receives a unique Certificate ID.

Example:

```text
GB-CERT-418F578D002E
```

The Certificate ID is automatically generated and retrieved from the GreenByte database.

It acts as a human-readable reference to the underlying evidence.

### Certificate

```text
/certificate/<certificate-id>
```

Shows the human-readable sustainability record.

### Proof

```text
/proof/<certificate-id>
```

Shows technical evidence such as:

```text
Evidence Hash
Methodology Hash
Block Hash
Previous Block Hash
Raw Evidence
Ledger Block
```

### Verify

```text
/verify/<certificate-id>
```

Recalculates and checks the stored evidence.

Possible result:

```text
✓ VERIFIED
```

or:

```text
✕ INVALID
```

# 📏 Measured vs Estimated

GreenByte intentionally labels the provenance of important parameters.

| Parameter | Status |
|---|---|
| Local input/output tokens | Runtime telemetry |
| Cloud input/output tokens | Runtime telemetry |
| Local GPU power | Measured |
| Local GPU energy | Telemetry-derived |
| Total laptop wall energy | Not yet measured |
| Cloud inference energy | Prototype estimate |
| PUE | Configured testing parameter |
| Carbon intensity | Configured testing parameter |
| ACU definition | GreenByte-defined |
| Certificate ID | Automatically generated |
| Evidence Hash | Cryptographically generated |
| Methodology Hash | Cryptographically generated |
| Block Hash | Cryptographically generated |

This separation is important because GreenByte does not present testing assumptions as directly measured environmental data.

# ⚠️ Current Limitations

The current prototype should not be interpreted as a final certified carbon-accounting platform.

In particular:

```text
616 J is a prototype Cloud energy estimate.

The current Cloud energy coefficients are not final calibrated values.

Current local and cloud carbon-intensity values are testing parameters.

GPU telemetry does not equal total laptop wall energy.

Different Cloud and Local models have different capabilities and tokenizers.

ACU is an internal project-defined unit.

The current ledger is single-node, not a fully distributed blockchain.

GreenByte certificates are project verification records, not government certificates or regulated carbon credits.
```
